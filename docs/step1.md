# Step1：基準書を読んで仕分けるAI検品アーム（推論のみ）

## 概要

文章で書かれた検査基準書をLLMが読み、流れてくる部品の画像をVLMが判定し、Franka（ロボットアーム）が良品箱とNG箱に仕分ける。
Step1では学習を行わず、AIの推論だけで動かす。

```
基準書（文章）──LLM──▶ 判定ルール（JSON）
                                │
部品がベルトで流れてくる → 検査カメラで真上から撮影 ──VLM──▶ OK / NG の判定
                                                           │
                                       Frankaがつかんで 青の箱（OK）/ 橙の箱（NG）に入れる
```

- シミュレータ：Genesis 1.4.5（GPU、画面なしで描画）
- ロボット：Franka Emika Panda
- LLM / VLM：Claude Opus 5.5（`claude-opus-5-5`）。LLMとVLMは同じモデルで、画像を渡すかどうかだけが違う
- アームの動作：スクリプト制御（部品の位置はシミュレーションの真値を使う）
- 見どころ：基準書を差し替えるだけで、同じ部品の仕分け先が変わる

## 部品と基準書

部品は一辺5cmの立方体で、上面だけを検査する。種類は次の5つ。

| 種類 | 見た目 | 大きさの範囲 |
|---|---|---|
| 良品 | 欠陥なし | — |
| 傷・小 | 黒い線 | 一辺に対する長さの比 0.08〜0.15 |
| 傷・大 | 黒い線 | 一辺に対する長さの比 0.6〜0.8 |
| 色ムラ・小 | 茶色の円 | 面積比 0.015〜0.03 |
| 色ムラ・大 | 茶色の円 | 面積比 0.25〜0.35 |

基準書は2種類。

| 基準書 | 内容 | 傷・小 | 色ムラ・小 |
|---|---|---|---|
| 標準（`standard.txt`） | 傷は一辺の1/3以上、色ムラは面積の10%以上でNG | OK | OK |
| 厳格（`strict.txt`） | 傷・色ムラが少しでもあればNG | NG | NG |

傷・大と色ムラ・大はどちらの基準書でもNG、良品はどちらでもOKになる。
正解のOK/NGは、部品を作ったときの欠陥の大きさと、設定ファイルのしきい値から計算する。

## 実行コマンド

すべてリポジトリの直下で実行する。APIキーは `.env` の `ANTHROPIC_API_KEY` に設定しておく。

### 1. 環境の確認

```
uv run python scripts/check_env.py
```

- GPUがPyTorchから使えるか、`.env` にAPIキーがあるか（キーの中身は表示しない）、Genesisで描画と録画ができるかを確認する
- 出力：`outputs/check_env/franka.mp4`

### 2. 部品の見た目と把持の確認

```
uv run python scripts/check_texture_grasp.py
```

- 良品・傷・色ムラの3個を真上から撮影し、上面に模様が出ているかを確認する
- 傷のある部品を1個つかんで持ち上げ、把持できるかを確認する
- 出力：`top.png`、`grasp.mp4`
- APIは呼ばない

### 3. 判定だけの試行

```
uv run python scripts/try_vlm.py --per-variant 2      # 撮影と判定
uv run python scripts/try_vlm.py --render-only        # 撮影のみ（APIは呼ばない）
```

- 部品を種類ごとに作って撮影し、2つの基準書それぞれでVLMに判定させ、正解率を出す（アームは動かさない）
- 出力：`outputs/try_vlm/`（`images/`、`results.jsonl`、`rules_*.json`）

### 4. Step1本体

```
# 動画付きで5個を仕分ける
uv run python scripts/run_step1.py --standard standard
uv run python scripts/run_step1.py --standard strict

# 50個で正解率と仕分け成功率を測る（動画なし）
uv run python scripts/run_step1.py --standard standard --per-variant 10 --seed 1 --no-video
uv run python scripts/run_step1.py --standard strict   --per-variant 10 --seed 1 --no-video

# 前回の判定結果を使い、APIを呼ばずに仕分けと録画だけやり直す
uv run python scripts/run_step1.py --standard standard --seed 0 --reuse-judgments
```

処理の流れ：

1. 5種類の部品を `--per-variant` 個ずつ作り、順番をシャッフルする（同じ `--seed` なら基準書が違っても同じ部品が同じ順で流れる）
2. LLMが基準書を読み、判定ルール（JSON）に変換する
3. 部品1個ごとに次を繰り返す
   1. ベルトで検査位置まで流す
   2. 検査カメラで真上から撮影する
   3. VLMが画像とルールから OK / NG を判定する
   4. Frankaがつかみ、判定に応じた箱に入れる（箱の4か所が埋まったら、次を入れる前に箱を空にする）
4. 正解と比べ、判定の正解数と、正しい箱に入った数を表示する

| オプション | 意味 |
|---|---|
| `--standard` | 使う基準書（`standard` / `strict`） |
| `--per-variant` | 種類ごとの部品の数（既定 1） |
| `--seed` | 部品を作るときの乱数の種（既定 0） |
| `--no-video` | 動画を作らない |
| `--reuse-judgments` | 保存済みの判定結果を使い、APIを呼ばない |

出力：`outputs/step1/<基準書>_seed<seed>/`

| ファイル | 内容 |
|---|---|
| `run.mp4` | 日本語字幕付きの動画。判定中は右上に検査カメラの画像を出し、枠の色で判定を示す（青=OK、橙=NG） |
| `rules.json` | LLMが基準書から作った判定ルール |
| `results.jsonl` | 部品ごとの記録（正解、VLMの判定・理由・推定した大きさ、把持できたか、箱に入ったか） |
| `images/` | VLMに渡した検査画像 |

### 5. 動画v1

`standard_seed0/run.mp4` と `strict_seed0/run.mp4` をffmpegでつないだもの（`outputs/step1/video_v1.mp4`、1分35秒）。
前半が標準、後半が厳格の基準書で、同じ5個の部品を仕分ける。

## プログラムの構成

| ファイル | 役割 |
|---|---|
| `configs/step1.yaml` | モデル名、シミュレーション、部品の大きさ、カメラ、基準書と正解計算用のしきい値 |
| `configs/standards/standard.txt` | 標準の基準書 |
| `configs/standards/strict.txt` | 厳格の基準書 |
| `src/inspection_arm/parts.py` | 部品の生成。欠陥を描いたテクスチャ付きの立方体（GLB）を作り、しきい値から正解を計算する |
| `src/inspection_arm/inspector.py` | Claudeの呼び出し。`read_standard`（基準書→ルール）、`judge`（画像＋ルール→判定）。出力はPydanticのモデルで形式を固定し、トークン数を数える |
| `src/inspection_arm/cell.py` | 検品セル。ベルト、2つの箱、Franka、カメラ、部品を流す動作、つかんで箱に入れる動作、字幕付きの録画 |
| `scripts/check_env.py` | 環境の確認 |
| `scripts/check_texture_grasp.py` | 部品の見た目と把持の確認 |
| `scripts/try_vlm.py` | 判定だけの試行 |
| `scripts/run_step1.py` | Step1本体 |

### LLMとVLMの役割

- LLM（`read_standard`）：基準書の文章を、欠陥の種類ごとの「NGになる条件」と「しきい値（大きさの比）」のJSONに変換する
- VLM（`judge`）：検査画像と上のルールを受け取り、判定（OK/NG）、欠陥の種類、推定した大きさの比、確信度、理由をJSONで返す

## 結果

| 確認したこと | 標準 | 厳格 |
|---|---|---|
| 判定の正解（50個、種類ごとに10個） | 50/50 | 50/50 |
| 正しい箱に入った数（50個） | 50/50 | 50/50 |
| 動画用の5個（判定 / 仕分け） | 5/5 / 5/5 | 5/5 / 5/5 |
| API費用（50個の評価） | 約0.45ドル | 約0.41ドル |

- 種類別に見ても、すべての種類で10/10だった
- 傷・小と色ムラ・小は、標準ではOK、厳格ではNGと判定され、基準書の差し替えで仕分け先が変わることを確認した
- VLMが推定した大きさの比は、実際の値とほぼ一致した（例：傷の長さ比 0.76 に対して推定 0.70）
- Step1全体のAPI費用は約1.2ドル

## 開発中に直した問題

| 問題 | 原因 | 対応 |
|---|---|---|
| 2個目以降の把持に失敗し、失敗が連鎖した | 手先が目標の高さまで下がり切らず、部品の上端しかつかめていなかった | つかむ高さを部品の中心に合わせ、降下後に手先が届くまで待つ |
| 同じ箱の部品が重なり、失敗と判定された | 箱の同じ場所に置いていた | 箱の中の4か所に順に置き、重なっても箱の中なら成功とする |
| 50個の評価で、仕分け成功率が19〜20/50になった | 内寸16cmの箱に25個を入れ続けて溢れた（判定は全問正解） | 4か所が埋まったら箱を空にする（満杯の箱の交換を想定）。保存済みの判定で仕分けだけやり直し、50/50を確認 |
| 部品の模様が側面に出た | GLBはY軸が上の座標系で、読み込み時に向きが変わる | 書き出す前に頂点の座標を逆変換する |
| Genesisの基本の箱形状に模様が出ない | 基本形状にはテクスチャ座標（UV）がない | UV付きの立方体メッシュを自作する |

## 制約

- アームの動きはスクリプトで決めており、部品の位置はシミュレーションの真値を使っている（画像から位置を読み取って動かすのはStep2のACTの役割）
- 欠陥は傷と色ムラの2種類だけ。基準書には「欠け」も書いてあるが、部品の見た目としては作っていない
- 部品の見た目は人工的に描いたもので、正解は描いたときの大きさから計算している
